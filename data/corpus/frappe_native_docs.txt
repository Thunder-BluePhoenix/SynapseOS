# Motto

> **"Your ERP. Your device. No compromises."**

frappe-native exists because mobile ERP has been done wrong for a decade.
WebViews dressed as apps. Clunky ports of desktop UIs. Tools that need internet to function.

frappe-native generates real native apps — not wrappers, not shells.
Apps that work in a warehouse with no signal.
Apps that sync when connectivity returns, silently and correctly.

- Offline is not a feature — it is the baseline

**Goal:** Given a Frappe DocType, automatically derive the mobile UI contract, offline data model, sync rules, and field mappings — without the developer writing any of this manually.

Developer installs frappe-native → selects "Sales Invoice" → system automatically produces:


**3. Sync Rules**
```json

  "offline_editable": ["draft"],

```

```python
        "doctype": doctype,
        "fields": [map_field(f) for f in meta.fields if not f.hidden],

        "is_submittable": meta.is_submittable,
```

## Auth Flow (frappe-gate)

```
First launch:
  1. User enters Frappe site URL + credentials
  2. App generates device fingerprint (OS + model + UUID)
  3. POST /gate/device/register → device_id returned
  4. Admin approves in Frappe desk
  5. POST /gate/token → JWT stored securely (flutter_secure_storage)

Subsequent launches:
  1. Check stored JWT expiry
  2. If valid → proceed
  3. If expired → POST /gate/token/refresh
  4. If refresh fails → re-login screen
```

## Typed Flutter SDK (PulseClient)

Bootstrapped once on first launch from `frappe_pulse.api.mobile.get_mobile_config`. Exposes typed methods — no raw HTTP in the rest of the codebase.

```dart
class PulseClient {
  final String baseUrl;
  final TokenManager tokenManager;
  late final PulseMobileConfig _config;

  Future init() async {
    final raw = await _get('/api/method/frappe_pulse.api.mobile.get_mobile_config');
    _config = PulseMobileConfig.fromJson(raw);
  }

  // Pull events since [after] — uses ?_mobile=1 + MessagePack by default
  Future> pull({required DateTime after}) async {
    final uri = Uri.parse('$baseUrl${_config.pullEndpoint}')
        .replace(queryParameters: {
          'after': after.toIso8601String(),
          '_mobile': '1',
          'node_id': _config.nodeId,
        });
    final token = await tokenManager.getValidToken();
    final response = await http.get(uri,
        headers: {'Authorization': 'Bearer $token', 'Accept': 'application/msgpack'});

    // Decode MessagePack → JSON → typed events
    final decoded = MessagePackCodec.decode(response.bodyBytes) as Map;
    return (decoded['events'] as List).map(PulseEvent.fromJson).toList();
  }

  // Push local events to the server
  Future> receive(List events) async {
    final token = await tokenManager.getValidToken();
    final response = await http.post(
      Uri.parse('$baseUrl${_config.receiveEndpoint}'),
      headers: {'Authorization': 'Bearer $token', 'Content-Type': 'application/json'},
      body: jsonEncode({'events': events.map((e) => e.toJson()).toList()}),
    );
    return Map.from(jsonDecode(response.body)['message']);
  }

  // Register FCM/APNs device token for push notifications
  Future registerPushToken(String token, String platform) async {
    await _post('/api/method/frappe_pulse.api.mobile.register_push_token',
        {'device_token': token, 'platform': platform});
  }
}
```

## Local Data Layer Architecture

```
App requests data
        ↓
LocalStore (SQLite)   ← primary read source always
        ↓
Background sync worker ← keeps SQLite fresh from Frappe
        ↓
frappe-pulse client    ← event push/pull
        ↓
Frappe server
```

App **never** waits for a network call to render a screen. SQLite is always the source of truth locally.

## SQLite Store

Auto-built from Phase 1 offline model contracts:

```dart
class LocalStore {
  final Database _db;

  Future initFromContract(List contracts) async {
    for (final contract in contracts) {
      await _db.execute(contract.sqliteSchema);
    }
  }

  Future?> getDoc(String doctype, String name) async {
    final rows = await _db.query(
      _tableName(doctype),
      where: 'name = ?',
      whereArgs: [name],
    );
    return rows.isEmpty ? null : rows.first;
  }

  Future upsertDoc(String doctype, Map doc, SyncState state) async {
    await _db.insert(
      _tableName(doctype),
      {...doc, '_sync_status': state.name, '_modified': DateTime.now().millisecondsSinceEpoch},
      conflictAlgorithm: ConflictAlgorithm.replace,
    );
  }
}
```

## frappe-pulse Client (Flutter side)

Uses `PulseClient` from Phase 3 (typed SDK). All pull calls automatically use `?_mobile=1` — the server strips non-essential fields and responds with MessagePack (~30% smaller than JSON). Decoded on the Flutter side using the `messagepack` package.

```dart
class PulseClient {
  // Push local pending events to frappe-pulse (JSON POST)
  Future pushPendingEvents() async {
    final pending = await localStore.getPendingEvents();
    if (pending.isEmpty) return;
    final result = await receive(pending);  // typed receive() call
    await localStore.markEventsSynced(pending.map((e) => e.eventId).toList());
  }

  // Pull new events from server — ?_mobile=1 + MessagePack automatically applied
  Future pullEvents() async {
    final lastSync = await localStore.getLastSyncTimestamp();
    final events = await pull(after: lastSync);  // typed pull() — strips + MessagePack
    for (final event in events) {
      await applyEvent(event);
    }
    await localStore.updateLastSyncTimestamp();
  }
}
```

## Sync Rules Enforcement (from Phase 1)

Not everything is creatable or editable offline:

```dart
bool canCreateOffline(String doctype) {
  return syncRules[doctype]?.offlineCreatable ?? false;
}

bool canEditOffline(String doctype, String status) {
  final editableStatuses = syncRules[doctype]?.offlineEditable ?? [];
  return editableStatuses.contains(status);
}
```

Submitted documents → read-only offline (no editing).
Draft documents → editable offline.
Cancelled documents → read-only everywhere.

## C Layer: SQLite Custom Extension

The only C code in frappe-native. SQLite's extension API is C-only — no other approach works here.

**One targeted extension: Encrypted Local Store (SQLite VFS)**

Mobile devices get lost or stolen. The local SQLite store holds real ERP data — customer records, invoices, stock levels. It must be encrypted at rest.

A custom C VFS (Virtual File System) intercepts SQLite's read/write calls and applies AES-256 encryption transparently. The Flutter app (`sqflite`) loads it on startup — no changes to any query or data layer code.

```c
/* pulse_mobile_vfs.c — AES-256 encrypted SQLite VFS for Flutter */
static int mobileVfsRead(sqlite3_file *pFile, void *zBuf, int iAmt, sqlite3_int64 iOfst) {
    MobileVfsFile *p = (MobileVfsFile *)pFile;
    int rc = p->pReal->pMethods->xRead(p->pReal, zBuf, iAmt, iOfst);
    if (rc == SQLITE_OK) aes256_decrypt(zBuf, iAmt, p->deviceKey);
    return rc;
}
```

The encryption key is derived from the device fingerprint + frappe-gate device token — so the database is bound to the specific registered device. Even if the SQLite file is extracted, it cannot be read on another device.

**Scope rule:** One C file. Loaded as a SQLite extension via `sqflite`'s native plugin bridge. No other C in frappe-native.

## Source Code Generator

```python
def generate_flutter_project(app_config_name: str) -> bytes:
    config = frappe.get_doc("Native App Config", app_config_name)
    screens = get_screens_for_app(app_config_name)

    # Render Flutter project from template
    project = FlutterProjectTemplate()
    project.set_app_name(config.app_name)
    project.set_bundle_id(config.app_id)
    project.set_primary_color(config.primary_color)
    project.set_logo(config.logo)
    project.set_site_url(config.frappe_site)
    project.embed_dsl(screens)

    return project.to_zip()
```

```dart
// On app startup — after JWT auth completes
final fcmToken = await FirebaseMessaging.instance.getToken();

// Token refresh
FirebaseMessaging.instance.onTokenRefresh.listen((newToken) {
  pulseClient.registerPushToken(newToken, platform);
});
```

**Notification handlers:**

```dart
// Foreground — show in-app snackbar
FirebaseMessaging.onMessage.listen((message) {
  final docType = message.data['event_doc_type'];
  final docName = message.data['event_doc_name'];
  ScaffoldMessenger.of(context).showSnackBar(
    SnackBar(content: Text('${message.notification?.title ?? docType} updated')),
  );
});

// Background / terminated — deep-link on tap
FirebaseMessaging.onMessageOpenedApp.listen((message) {
  final docType = message.data['event_doc_type'];
  final docName = message.data['event_doc_name'];
  if (docType != null && docName != null) {
    AppRouter.push(DetailScreen(doctype: docType, name: docName));
  }
});
```

# frappe-native — Build Plan

**One line:** Native mobile app generator for Frappe — offline-first, sync-ready, no wrapper.

---

## What We Are Building

A Frappe app that reads DocType definitions and generates real native mobile apps (Flutter) with offline storage, sync via frappe-pulse, and a Layout DSL that lets developers customize mobile UI without rebuilding the app.

```
Frappe DocType definition
        ↓
frappe-native (Frappe app)
├── Schema → Experience Engine   (auto-generates UI contract + offline model)
├── Layout DSL                   (developer customizes screens in JSON)
├── Mobile Builder UI            (drag-drop in Frappe desk)
└── App Generator                (produces Flutter project or live config)
        ↓
Flutter App (Android + iOS)
├── Dynamic UI renderer          (reads Layout DSL from server)
├── Local SQLite store           (offline-first data layer)
├── Sync engine client           (talks to frappe-pulse)
└── frappe-gate client           (device auth + token management)
```

---

## What We Are NOT Building

- Not a WebView wrapper
- Not a Frappe desk port to mobile
- Not a cloud-only product
- Not a no-code platform (developers configure, not end users)
- Not dependent on always-on internet

---

## Dependency Stack

frappe-native sits on top of the other two products:

```
frappe-native   ← this product (mobile + generator)
frappe-pulse    ← sync engine (required)
frappe-gate     ← access security (required)
```

frappe-pulse must be installed for sync to work.
frappe-gate must be installed for device authentication.

---

## Phases Overview

| Phase | Name | Output |
|-------|------|--------|
| 1 | Schema → Experience Engine | Auto-generate UI contract + offline model from DocType |
| 2 | Layout DSL | JSON-based screen definition, hot-reload in app |
| 3 | Flutter Core App | Base app: auth, local DB, dynamic UI renderer |
| 4 | Offline Engine | SQLite store, sync state UI, conflict indicators |
| 5 | Mobile Builder UI | Drag-drop screen builder inside Frappe desk |
| 6 | App Generator | Export Flutter source / generate APK / live config mode |
| 7 | Device Capabilities | Camera, GPS, barcode scanner, Bluetooth integration |
| 8 | App Templates | Retail, warehouse, CRM, field service starter packs |

---

## Tech Stack

| Layer | Tech | Reason |
|-------|------|--------|
| Frappe app (backend) | Python | DocType integration, API, builder UI |
| Mobile framework | Flutter | Cross-platform, native performance, rich UI |
| Local database | SQLite (via `sqflite`) | Lightweight, offline-first |
| Sync client | frappe-pulse protocol | Event-based, conflict-aware |
| Auth client | frappe-gate JWT | Device identity, short-lived tokens |
| Layout DSL | JSON (custom schema) | Hot-reloadable, no rebuild needed |
| UI rendering | Flutter widget engine | DSL → widgets at runtime |
